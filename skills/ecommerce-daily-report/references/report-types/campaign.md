# 大促监控



活动进度、费用与供给是否匹配，哪个环节需要及时调整？



最低资料：活动计划与阶段成交可做进度观察；费用、库存和执行记录分别支撑专项模块。



## 可用模块



### 活动阶段进度

问题：在当前活动阶段，进展是否偏离计划？

方法角色：AG07、AG08

输入：活动计划与阶段成交

维度：活动阶段、渠道、商品

指标：阶段与累计成交：区分预售、支付和完成口径，避免定金与尾款重复计入；阶段达成：同阶段实际 ÷ 对应阶段目标；无阶段目标时仅展示实际

图形意图：阶段累计进度图、同进程对比

成立条件：与同活动阶段或相同经过时长比较，不能用当前小时对比往期全天。

建议：把阶段差距定位到可协调的渠道或商品。

验证：在后续同阶段口径下复查，同时保留活动配置变化。



### 费用与活动质量

问题：成交进度是否伴随不合预期的费用或退款变化？

方法角色：AG14、AG06

输入：费用预算、成交及可用售后资料

维度：渠道、阶段、计划

指标：费用与预算执行：匹配活动阶段及预算范围；归因效率与售后观察：分别按归因窗和订单队列记录，未成熟部分保持待观察

图形意图：费用与进度对照、阶段效率趋势

成立条件：归因成交不与总成交直接相加；退款滞后不得忽略。

建议：形成费用或资源调整的核查建议，交负责人确认。

验证：在回传和售后观察条件可比时，评估调整后的活动质量。



### 保供与活动执行

问题：供给、页面或履约问题是否妨碍活动推进？

方法角色：AG02、AG04、AG07

输入：库存、履约、活动配置与变更记录

维度：重点商品、环节、责任岗位

指标：重点商品供给状态：关联活动需求条件、可售库存及有效在途；执行事项状态：记录配置、履约和库存问题的发现、处理与生效时间

图形意图：供需时间线、活动问题清单

成立条件：活动需求不能直接套用平销均值；没有记录不能推断执行异常。

建议：优先协调会影响当前活动阶段的具体问题。

验证：确认问题修正已生效，再复查活动进度和履约表现。



## 口径规则

- 活动进度按阶段和相同经过时长比较，区分日报与小时监控。

- 目标、预算和统计范围随活动版本保留，不事后改口径来解释结果。

- 定金、尾款、支付和退款的处理需先约定，避免重复计入。

- 调整建议需保留生效时间，为活动复盘提供可追溯记录。
