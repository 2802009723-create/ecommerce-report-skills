# 店铺运营



成交变化出现在流量、转化还是客单环节？



最低资料：成交资料可形成结果模块；有同范围流量与买家数据后才分析转化。



## 可用模块



### 成交表现

问题：成交规模和结构发生了什么变化？

方法角色：AG03

输入：店铺成交

维度：店铺、日期、商品组

指标：支付金额与订单数：使用同一支付状态、统计周期和店铺范围；客单指标：明确采用支付金额 ÷ 支付买家数，或订单均额；两者分别命名

图形意图：成交趋势、结构对比图

成立条件：不把部分日数据直接与完整日比较；零分母不计算客单指标。

建议：定位发生变化的商品或业务时段。

验证：复查同范围成交及客单变化，排除订单状态口径变化。



### 流量与支付转化

问题：流量数量、来源或转化哪个环节需要关注？

方法角色：AG03

输入：店铺成交、流量与转化

维度：来源、商品、设备或时段（以资料字段为准）

指标：访客与来源结构：按相同去重层级汇总；来源不可去重时说明重叠；支付转化率：同范围支付买家数 ÷ 访客数；分母为零时不计算

图形意图：流量与转化分图、来源对比；事件链一致时才用漏斗

成立条件：跨来源重叠访客不能直接相加；百分点变化与相对变化分别表达。

建议：核查异常来源或商品的价格、页面与供给变化。

验证：按同一来源和商品观察后续转化，原因需有额外证据支持。



### 运营异常与整改

问题：哪个可核查的运营问题可能影响成交？

方法角色：AG15、AG02

输入：运营变更与履约记录

维度：问题类型、商品、发生时间

指标：异常记录：将页面、价格、缺货或履约记录关联到商品与生效时间；整改进度：记录已执行动作、待确认项与效果验证状态

图形意图：事件时间线、问题明细

成立条件：时间重合只能提示关联，不能单独证明因果；相关专家按问题加入。

建议：提交具体核查与修正事项，保留变更前后记录。

验证：确认修正已生效，再用可比窗口评估表现；同期活动作为影响因素记录。



## 口径规则

- 固定支付金额、净成交、订单数和买家数的定义。

- 大促或节假日应标记，必要时使用同阶段或同星期基准。

- 没有连续事件链时，访客、加购和支付只做分项对比，不强行画转化漏斗。

- 缺货或页面变更只作为可核查线索，不能直接认定为成交波动原因。
