# 客服售后



用户遇到了什么问题，哪些售后事项还未解决，处理质量怎样？



最低资料：咨询或工单资料可形成问题与处理模块；退款率需要可关联的订单队列及观察窗口。



## 可用模块



### 咨询与客诉主题

问题：哪些问题重复出现，关联哪些商品或环节？

方法角色：AG18

输入：咨询、评价与工单

维度：问题主题、商品、服务环节

指标：问题主题数量与分布：按约定去重规则归类；同一工单多次消息不重复算事件；影响范围：关联商品、订单或流程环节，并标明样本覆盖

图形意图：问题主题排行、商品问题矩阵

成立条件：未核实的用户描述作为反馈记录，不直接判定商品或服务责任。

建议：将重复问题转为商品信息、服务流程或履约核查。

验证：在可比咨询量和分类口径下复查同类问题变化。



### 处理进度与答复一致性

问题：哪些问题积压，答复是否符合已提供的规则？

方法角色：AG19、AG22

输入：处理记录、工单状态及政策资料

维度：问题类型、责任环节、处理阶段

指标：新增、已解决与未结：区分当日流入、当日流出和期末存量；状态变更要可追踪；服务时效与答复检查：时效明确起止事件与工作时段；答复对照适用政策版本

图形意图：工单流入流出、积压时长分布

成立条件：答复一致性只按已提供的政策核对；无时间记录不推算响应时效。

建议：明确升级处理对象，修正知识条目或流程说明。

验证：核对未结事项是否解决，以及后续答复是否持续符合规则。



### 退款退货结果

问题：售后损失发生在哪里，哪些订单队列需要跟进？

方法角色：AG20

输入：退款退货与可关联原订单

维度：原因、商品、原订单队列、处理状态

指标：当日申请与完成量：按事件发生日分别记录，申请金额与实际退款金额分开；订单队列退款率：同一原始订单队列中的退款订单数 ÷ 队列订单数，注明观察窗口

图形意图：售后队列趋势、原因结构和处理明细

成立条件：不能用今日退款订单除以今日新订单；未成熟队列标为持续观察。

建议：跟进主要退款原因与未完成事项，保留可核查的处理记录。

验证：在队列和观察窗口可比时复查退款结果，避免时滞造成误判。



## 口径规则

- 咨询消息数、工单数、订单数和客户数分别定义。

- 当日新增 / 处理量与期末积压分别展示，避免把流量和存量混用。

- 退款事件发生日与原订单归属期分开；比率需要固定订单队列。

- 正文使用去标识化的问题摘要，原始客户记录按需要保留受控引用。
