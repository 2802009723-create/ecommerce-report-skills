# 新品观察



新品是否具备继续测试的条件，当前信号支持什么，下一步验证什么？



最低资料：新品标识、上市时间及成交资料可作早期观察；流量、反馈和测试记录支撑具体判断。



## 可用模块



### 上市条件与准备度

问题：影响测试的商品、供给和页面条件是否齐备？

方法角色：AG13、AG15

输入：新品档案、准备清单与变更记录

维度：商品、准备环节、上市阶段

指标：准备项状态：依据已确认的上市清单逐项核对，不预设完成状态；条件变更：记录价格、库存、详情和渠道开放时间

图形意图：准备项清单、上市事件时间线

成立条件：有记录才能认定完成；缺条件时说明它对测试解释的限制。

建议：先补齐会影响测试有效性的准备项。

验证：确认条件实际生效，并在后续观察中保留变更时间。



### 早期需求与转化信号

问题：在当前流量与价格条件下观察到了什么？

方法角色：AG13、AG03

输入：上市时间、早期流量与成交

维度：上市日龄、来源、商品

指标：访问、买家与成交：标明上市日龄、来源与样本规模；转化与可比表现：只有口径和观察窗口可比时计算，分母为零时不计算

图形意图：按上市日龄的趋势、同条件商品对照

成立条件：不直接与成熟商品绝对规模比较；样本不足时不作确定的成败判断。

建议：提出下一轮需要补充流量或验证的具体问题。

验证：在约定观察窗口复查，并记录价格、流量与供给条件变化。



### 反馈与下一轮测试

问题：哪些反馈可以转为可验证的改进假设？

方法角色：AG13、AG18、AG12

输入：用户反馈、测试假设及执行记录

维度：假设、版本、问题主题

指标：反馈主题与疑问：去重并保留商品、来源、时间和样本范围；测试结果状态：区分未开始、执行中、待观察与已有证据支持的结论

图形意图：假设与证据清单、测试时间线

成立条件：测试缺少可比条件时只报告关联；涉及价格时需补齐方案约束。

建议：把产品信息、价格或内容问题转为有验收标准的测试任务。

验证：按预设假设与标准判断继续、调整或终止，记录证据及不确定性。



## 口径规则

- 按上市相对日龄和可比流量条件观察，不直接套用成熟商品标准。

- 样本规模与观察窗口必须可见，小样本只提供方向性线索。

- 价格、详情和供给变更需关联测试版本，避免多项同时改动后单因归因。

- 继续测试、调整或终止依据事先约定的标准，不能事后挑选有利指标。
