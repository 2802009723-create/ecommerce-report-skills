# 直播运营



哪场直播、哪个时段或商品影响结果，下一场如何验证改进？



最低资料：场次标识与成交资料可做场次结果；链路、排品和费用需对应同一场次。



## 可用模块



### 场次结果与可比性

问题：本次场次表现怎样，哪些场次值得复查？

方法角色：AG17

输入：场次与成交、开播时长

维度：场次、时段、直播渠道

指标：场次成交与支付买家：按场次和订单关联去重，明确退款处理；单位时长指标：使用实际开播时长归一，仍需说明流量与活动条件差异

图形意图：场次对比、同进程累计曲线

成立条件：不同开播时长不直接比较累计量；同一订单不在场次汇总中重复计入。

建议：确定需要复查的场次、时段和链路节点。

验证：在可比时长和条件下观察后续场次，不以单场波动判定稳定效果。



### 观看到成交链路

问题：流量进入、停留或商品转化哪个环节需核查？

方法角色：AG17、AG14

输入：观看、互动、点击与支付链路

维度：场次、时段、商品

指标：进入、互动与商品点击：保留平台字段定义及统计范围；链路转化率：仅对可衔接的去重人群或事件计算，清楚列出分子分母

图形意图：条件一致时的漏斗；否则分别展示趋势

成立条件：曝光次数、观看人数与点击人次不可直接拼成单一人数漏斗。

建议：把链路异常与流量来源、脚本或场控记录一起核查。

验证：后续场次复查同定义的链路指标，说明流量来源变化。



### 排品与下一场改进

问题：排品、内容或供给哪项改动有证据支持？

方法角色：AG17、AG16、AG02

输入：排品、脚本、价格、库存与时段成交

维度：商品、讲解时段、内容节点

指标：商品上架与成交：关联商品讲解时段、价格和成交，避免仅凭销量评判讲解效果；改动与执行记录：保存排品、脚本和供给变更版本

图形意图：排品时间线、商品表现对照

成立条件：价格、人群、讲解时长和供给差异需一同记录，不能单因归责。

建议：为下一场形成明确的排品或内容验证任务。

验证：按预先约定的观察指标复查，分别判断执行完成与表现变化。



## 口径规则

- 场次为主要分析单位，跨日归属、开播时长与渠道定义必须一致。

- 人数、次数与人次分开；链路不一致时不生成看似完整的漏斗。

- 直播成交与广告归因成交可能重叠，不能简单求和。

- 下一场建议写成可验证的改动，避免用一场结果下长期结论。
